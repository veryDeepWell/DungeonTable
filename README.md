# DungeonTable

Рабочая версия 0.2 с простой тёмной вёрсткой. Клиент находится в `index.html` в корне и работает на GitHub Pages. Sites не используется. Внешних npm-зависимостей нет.

## Быстро посмотреть

1. Установленный Node.js должен быть версии **22.13 или новее** с модулем `node:sqlite`.
2. Запустите **start-local.cmd** либо выполните `npm start` в папке проекта.
3. Откройте **http://127.0.0.1:8787**.

На первом запуске доступна демонстрационная кампания. По умолчанию открыт локальный режим ГМ: можно сразу редактировать стол без создания комнаты. Данные этого режима сохраняются в IndexedDB браузера. Обычное открытие HTML двойным кликом не подходит для ES-модулей — используйте локальный сервер или GitHub Pages.

## Что попробовать

1. Перетащите Эйрин. Колесо мыши меняет масштаб, перетаскивание пустого места двигает камеру. «Вписать» возвращает всю сцену. Кнопка «Сетка» меняет привязку токенов.
2. Нажмите токен → «Лист»: доступны характеристики, владения, навыки, HP, заметки и ручное развитие.
3. Откройте «Инвентарь»: достаньте часть зелий на стол, подберите их, откройте сундук как ГМ, наденьте оружие/броню, передайте предмет.
4. «Сцены» → «Загрузить карту». Изображение уменьшается максимум до 2048 пикселей и разбивается на фрагменты. Инструмент «Раскрытие карты» переключает доступ к фрагменту. Закрытая графика не включается в данные игроков.
5. «Библиотека» → «Объект из картинки», либо создайте предмет и назначьте ему картинку. Объект на столе перетаскивается; **Alt + клик** открывает размеры, поворот, скрытие и удаление. Для портрета используйте кнопку персонажа.
6. «В бой»: сначала выберите участников и стороны. После подтверждения бросится инициатива. Shift + клик по токену назначает цель; нажмите оружие в панели героя.
7. При выключенном быстром применении ГМ видит ожидающий урон в панели персонажа. Сначала примените или отклоните его, затем завершайте ход.
8. Добавьте эффект с бонусом/костью/преимуществом и посмотрите подробный расчёт в журнале. Назначьте проверку игроку через панель ГМ.
9. «Настройки» → «Тактическое движение» ограничивает движение скоростью в текущем бою. «Бюджет хода» в панели ГМ позволяет вручную учесть дополнительные атаки и особые способности.
10. «Файлы» → экспорт создаёт JSON-архив с вложенными картинками. Импорт заменяет текущую кампанию после подтверждения. Отмена последнего изменения доступна ГМ в настройках; исходные броски остаются в журнале.

«Что работает» в верхней строке содержит актуальный перечень возможностей и ограничений. Подробное сравнение с ТЗ — в [docs/STATUS.md](docs/STATUS.md).

## Проверить комнату локально

1. Оставьте сервер `npm start` запущенным.
2. В приложении нажмите «Комната» → «Создать комнату».
3. Оставьте поле реестра пустым и адрес `http://127.0.0.1:8787`. Вставьте **ключ хозяина из data/admin-key.txt**, имя комнаты, пароль и имя ГМ. Этот ключ генерируется при первом запуске и не передаётся игрокам.
4. Для второй роли используйте приватное окно браузера/другой профиль: «Комната» → «Войти игроком», тот же сервер, имя комнаты и пароль.
5. В окне ГМ откройте «Участники» и назначьте персонажа игроку. Он получит управление только этим персонажем. Сторона в бою не равна владельцу.
6. Вход запоминается для этого браузера. При повторном открытии нажмите «Восстановить вход». Если ключ потерян, ГМ выдаёт новый через «Участники»; он передаётся только нужному игроку и отзывает старый.

Роли нельзя проверить двумя обычными вкладками одного браузера: они делят сохранённый ключ комнаты и локальное хранилище. Для быстрой проверки отображения без сервера есть переключатель «Локальный вид игрока»; это предпросмотр на доверенном компьютере ГМ, а не средство защиты файлов от владельца этого компьютера.

## Настроить GitHub Pages и Cloudflare один раз

1. Опубликуйте клиент на GitHub Pages: `index.html`, `config.js`, папка `src`, файл `.nojekyll`. Можно использовать корень ветки репозитория. Данные `data/`, файлы `*.local.json` и ключи **не публикуются**; они включены в `.gitignore`. В репозиторий можно добавить серверные исходники без каталога данных, но клиенту они не нужны.
2. Создайте отдельный Worker для DungeonTable по `cloudflare/wrangler.jsonc`. В `CLIENT_ORIGIN` указывается только origin сайта, например `https://verydeepwell.github.io`, без пути `/DungeonTable/`.
3. В каталоге `cloudflare` при установленном Cloudflare Wrangler выполните `wrangler secret put HOST_KEY`, затем `wrangler deploy`. Выберите собственный длинный случайный ключ. Не используйте ключи/единственный слот реестра Table.
4. В публичном `config.js` впишите **только адрес Worker** в поле `registry`; секретных ключей здесь нет.
5. На ПК хоста нужны Python 3 и cloudflared. Запустите `start-online.cmd` или `python host.py`.
6. Первый запуск запросит адрес Worker, HOST_KEY и origin клиента. Настройки хранятся только в `data/host.local.json`. Повторная настройка: `python host.py --setup`.
7. Запускатель поднимает Node.js на loopback, Cloudflare Tunnel и регистрацию хоста. Продление каждые 12 секунд, срок аренды 45 секунд. Перезапуск может менять адрес туннеля, браузер находит новый через Worker.
8. На GitHub Pages создайте комнату с **ключом хозяина Node.js из data/admin-key.txt**. Это другой ключ, чем HOST_KEY реестра. Друзья входят по имени комнаты и паролю, каждый получает свой личный ключ.

Подключение через HTTPS-клиент использует HTTPS-адрес туннеля. Не отключайте защиту браузера ради подключения к незашифрованному адресу. Постоянная регистрация в Cloudflare, загрузка Worker и проверка через реальные внешние сети выполняются владельцем аккаунта; в этой версии они не развёрнуты автоматически.

**Ограничения Quick Tunnel** и доступность Cloudflare в сетях всех участников нужно проверить перед настоящей длительной партией. Подключение не является автономным P2P: игровой трафик проходит через Cloudflare, данные кампаний сохраняются на ПК хоста. Реестр хранит только адрес хоста. Уже подключённый клиент продолжает использовать работающий адрес, даже если запись реестра временно истекла.

## Хранение

- Локальная подготовка: IndexedDB браузера, отдельная от серверной кампании.
- Сетевая кампания: `data/dungeon.sqlite`, режим WAL, транзакционная запись команд и результатов; повторный ID команды распознаётся после перезапуска.
- Картинки в этой версии находятся внутри сериализованной кампании SQLite/JSON, а не в отдельном файловом blob-хранилище. Обычные сетевые представления содержат только метаданные разрешённых картинок, сами изображения загружаются отдельно по личному ключу. Общий лимит — около 24 МБ бинарной графики кампании.
- Последние 20 изменяющих команд доступны для отмены. Снимки содержат изображения и могут увеличить размер базы. Автоматические резервные копии по расписанию пока не реализованы — экспортируйте кампанию вручную.
- Для файловой резервной копии SQLite сначала остановите сервер, затем копируйте весь каталог `data/`. Не копируйте только открытый `.sqlite`, игнорируя его WAL-файлы.
- Состояние боёв, комнаты, назначенные владельцы и личные ключи восстанавливаются после остановки процесса. Закрытие вкладки ГМ не останавливает сервер. Автоматическая остановка боя при исчезновении ГМ пока не реализована: просто не выполняйте следующие ходы до его возвращения.

## Проверки

`npm test` — проверки ядра, синтетического DOM и настоящих локальных HTTP-запросов с несколькими ключами, перезапуском SQLite, повторами и ошибочными командами. `npm run check` — синтаксис JS-модулей. `python -m py_compile host.py` — синтаксис запускателя.

Проверка интерфейса реальным браузером и соединение двух реальных удалённых компьютеров не подтверждены. Встроенная автоматическая проверка DOM не заменяет их. Worker и cloudflared требуют отдельной проверки в окружении аккаунта владельца.
